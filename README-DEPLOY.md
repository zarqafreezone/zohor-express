## 🚀 الطريقة الأولى: Render.com (الأسرع — 10 دقائق)

### الخطوة 1: حساب GitHub
1. افتح `https://github.com/signup` وسجّل حساباً مجانياً (البريد + كلمة مرور + اسم مستخدم).

### الخطوة 2: رفع ملفات التطبيق
1. بعد الدخول لـ GitHub اضغط زر **+** أعلى اليمين ثم **New repository**.
2. الاسم: `zohor-express` — اجعله **Public** — اضغط **Create repository**.
3. في صفحة المستودع الجديد اضغط رابط **uploading an existing file**.
4. من مجلد `zohor-express` اسحب **محتويات** المجلد (وليس المجلد نفسه) إلى المتصفح:
   - `server.js` و `package.json` و `render.yaml` و `Dockerfile`
   - مجلد `public` كاملاً (داخله 5 صفحات + js + css)
5. انتظر الرفع ثم اضغط **Commit changes**.

### الخطوة 3: النشر على Render
1. افتح `https://render.com` → **Get Started** → سجّل الدخول **بحساب GitHub**.
2. من اللوحة اضغط **New +** → **Web Service**.
3. اختر المستودع `zohor-express` → **Connect**.
4. اترك الإعدادات كما هي (سيتعرف عليها تلقائياً من `render.yaml`):
   - Runtime: Node | Build: `npm install` | Start: `npm start`
   - Instance Type: **Free**
5. اضغط **Create Web Service** وانتظر دقيقتين.
6. 🎉 ستحصل على رابط مثل:
   `https://zohor-express.onrender.com`

هذا هو رابط تطبيقك الحقيقي — أرسله للزبائن والسائقين، وافتحه في أي جوال.

### ⚠️ حدود الخطة المجانية في Render (مهم بصراحة)
1. **النوم:** إذا لم يزر أحد التطبيق لـ 15 دقيقة ينام الخادم، وأول زيارة بعده تتأخر دقيقة تقريباً.
   - **حل مجاني:** سجّل في `https://uptimerobot.com` (مجاني) وأضف Monitor من نوع HTTP على رابط تطبيقك كل 10 دقائق — يبقى التطبيق صاحياً 24 ساعة.
2. **البيانات:** عند نوم الخادم أو إعادة النشر تعود قاعدة البيانات لحالتها الأولى (تُمسح الطلبات الجديدة).
   - مقبول للتجربة والبداية، **غير مقبول لطلبات حقيقية طويلة المدى** → عند نجاح التطبيق انتقل لخيار Oracle أو الترقية المدفوعة، أو أخبرني لأربط التطبيق بقاعدة بيانات سحابية مجانية دائمة (مثل Neon/Supabase) وأجهّزها لك.

## 🏆 الطريقة الثانية: Oracle Cloud Always Free (خادم حقيقي دائم مجاناً)

خادم كامل يعمل 24/7 بدون نوم وبياناته محفوظة — الأنسب للتشغيل الفعلي.

1. سجّل في `https://cloud.oracle.com` (يطلب بطاقة للتحقق من الهوية — **لن يتم أي خصم** ضمن Always Free).
2. أنشئ **VM Instance** واختر الشكل **Always Free** (Ampere A1 أو VM.Standard.E2.1.Micro) بنظام Ubuntu.
3. اتصل بالخادم عبر SSH ثم أعطني كلمة «جاهز» وسأعطيك الأوامر سطراً سطراً:
   - تثبيت Node.js → رفع ملفات التطبيق → تشغيله بـ pm2 (يعيد تشغيله تلقائياً لو توقف) → فتح المنفذ 80 → يعمل على IP عام حقيقي (ويمكن ربط دومين مثل `zohor.jo` لاحقاً).

## 🏪 الطريقة الثالثة: جهاز في المحل + Cloudflare Tunnel

تشغّل التطبيق على أي كمبيوتر في المحل (Node.js + `npm start`) وتنفّذ `cloudflared tunnel` فيعطيك رابط https عاماً يصل لجهازك من الإنترنت — بدون فتح أي إعدادات راوتر. البيانات تبقى على جهازك. يتطلب بقاء الجهاز مشغّلاً، ولوطة ثابتة تحتاج دوميناً رخيصاً (~10$ سنوياً).

## 📦 ملفات المشروع المرفوعة

```
zohor-express/
├── server.js        ← الخادم الكامل (API + كل المنطق)
├── package.json     ← تعريف المشروع وأمر التشغيل
├── render.yaml      ← إعدادات النشر التلقائي على Render
├── Dockerfile       ← للنشر على أي منصة تدعم Docker
└── public/
    ├── index.html   ← الصفحة الرئيسية
    ├── customer.html ← واجهة الزبون
    ├── shop.html    ← لوحة المحل
    ├── driver.html  ← لوحة السائق
    ├── admin.html   ← لوحة الإدارة (Zohor@2026)
    ├── css/style.css
    └── js/ (common, sounds, customer, shop, driver, admin)
```

**ملاحظات تشغيلية مهمة:**
- لا يحتاج التطبيق أي قواعد بيانات خارجية — يخزن في `data/db.json` تلقائياً.
- كلمة مرور الإدارة في `server.js` داخل `settings.adminPassword` — **غيّرها قبل التشغيل الفعلي**.
- رسوم التوصيل (0.50) والاشتراك (10) والعمولة (0.20) قابلة للتعديل من ثوابت أعلى `server.js`.
- لنسخ احتياطي: حمّل ملف `data/db.json` دورياً (يحتوي كل شيء).

### 🔊 التنبيهات الصوتية المميزة (sounds.js)

## 🗄️ ربط قاعدة بيانات دائمة (Neon PostgreSQL) — حتى لا تُفقد الطلبات والحسابات أبداً

الكود جاهز بوضعين: بدون قاعدة بيانات يعمل بالملف (تجربة)، ومع `DATABASE_URL` يخزّن في PostgreSQL سحابي دائم (إنتاج).

### خطوات إنشاء قاعدة Neon المجانية (من طرفك — 5 دقائق)
1. افتح `https://neon.tech` → **Sign Up** (يمكن الدخول بحساب GitHub).
2. من لوحة Neon: **Create project** → الاسم: `zohor` → Region: الأقرب (Frankfurt/AWS) → **Create**.
3. في صفحة المشروع ستجد **Connection string** يبدأ هكذا:
   `postgresql://neondb_owner:كلمة_سر@ep-xxxx-pooler.eu-central-1.aws.neon.tech/neondb`
4. اضغط زر النسخ — هذه هي سلسلة الاتصال.

### إدخالها في Render (دقيقة)
1. dashboard.render.com → خدمتك → **Environment** (يسار).
2. **Add Environment Variable**:
   - Key: `DATABASE_URL`
   - Value: الصق سلسلة الاتصال كاملة
3. **Save changes** ← سيعيد Render النشر تلقائياً.
4. من Logs ستشاهد: `🗄️ التخزين: PostgreSQL سحابي دائم` ثم `✅ حُمّلت البيانات من السحابة`.

### ماذا سيحدث عند أول تشغيل سحابي؟
- إن وُجد ملف بيانات قديم في الخادم → **يُستورد تلقائياً** (ترحيل كامل لمحلاتك وطلباتك).
- إن لم يوجد → بيانات أولى نظيفة.
- من بعدها: **كل حساب واشتراك وطلب يُحفظ في السحابة فوراً ولا يُمسح مهما حدث** (تحديث كود، إعادة نشر، نوم).

ملاحظة: حافظ على الحد المجاني في Neon (0.5 GB — يكفي سنوات لعملك الحالي).

## 🔐 التحصينات الأمنية (مدمجة تلقائياً)

- **تشفير كلمات المرور** (scrypt): الإدارة + المحلات + السائقون — لا نص صريح في القاعدة إطلاقاً، والترقية تتم تلقائياً عند أول تشغيل.
- **كلمة مرور للسائقين**: إلزامية للسائقين الجدد، والقدامى تُطلب منهم واحدة عند أول دخول (شاشة تأمين الحساب) — رقم الجوال وحده لا يكفي لدخول أي أحد.
- **حماية من التخمين**: 5 محاولات خاطئة لكلمة مرور الإدارة = قفل الدخول 10 دقائق.
- **جلسة الإدارة تنتهي بعد 30 يوماً** وتجدد تلقائياً مع كل دخول جديد.

## 🗄️ النسخ الاحتياطية التلقائية (مجانية)

- نسخة عند كل إقلاع + نسخة كل 24 ساعة — تُحفظ في جدول `app_backups` داخل Neon (آخر 7 فقط).
- في وضع الملف المحلي: مجلد `data/backups/` (آخر 7).
- **عند انقطاع الاتصال بالسحابة أثناء العمل**: كل حفظ فاشل يكتب لقطة طوارئ في `data/emergency-last.json` ويعيد المحاولة كل 10 ثوانٍ تلقائياً حتى عودة الاتصال — لا ضياع صامت للبيانات.

## 🧪 بيئة تجريبية منفصلة (Staging) — قبل لمس الإنتاج

1. في Neon: افتح مشروعك → **Branches** → أنشئ فرعاً جديداً (مجاني) → انسخ رابط اتصال الفرع.
2. في Render: **New + → Web Service** → نفس مستودع GitHub → اسم مختلف (مثل `z-express-test`) → في Environment ضع `DATABASE_URL` رابط **الفرع التجريبي**.
3. جرّب كل تحديث على الرابط التجريبي أولاً، ثم ارفع للإنتاج بطمأنينة.
